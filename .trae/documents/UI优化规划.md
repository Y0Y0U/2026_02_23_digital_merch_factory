## 背景与目标

本插件当前 UI 集中在一个 N 面板主面板中（见 [panels.py](file:///e:/b-2_code/2026_02_23_digital_merch_factory/ui/panels.py)），整体结构已经具备“状态区 → 核心操作 → 参数区（可折叠）→ 管理区”的雏形。下一步优化建议围绕两条主线推进：

* 更符合人类操作习惯：以“流程/任务”为主线，而不是以“参数类型”为主线；减少用户在面板里来回找开关与参数的成本。

* 更贴近 Blender 原生外观：使用 Blender 推荐的 Panel 层级、标准布局与最少布局代码，避免自定义“伪折叠”的重复 UI 代码与状态字段膨胀。

## Blender 官方建议（与本项目直接相关）

建议以 Blender 官方 Python API 文档中关于 UI 与面板的约定为基准：

* 面板层级：使用 `bl_parent_id` 将面板拆分为子面板（Sub-panel），让 Blender 自动提供折叠与排序能力（见 [Panel](https://docs.blender.org/api/current/bpy.types.Panel.html) 的 `bl_parent_id`、`bl_order`）。

* UI 布局最佳实践：布局声明应尽量少，避免“布局代码比属性绘制还多”的情况（见 [Best Practice / User Interface Layout](https://docs.blender.org/api/current/info_best_practice.html)）。

* 布局 API：`row/column/split/box` 的语义与约束，及 `layout.use_property_split / use_property_decorate` 的标准属性对齐风格（见 [UILayout](https://docs.blender.org/api/current/bpy.types.UILayout.html)）。

## UI 信息架构草案（分类 / 分组 / 交互）

### 顶层结构（建议：1 个主面板 + 多个子面板）

将现有“一个面板塞所有功能”的结构拆成以下层级（均在 `VIEW_3D`/`UI`、同一 `bl_category = "Acrylic"` 下）：

1. 主面板：总览 + 主入口（永远可见，尽量短）
2. 子面板：按“流程步骤”拆分，默认只展开常用项，其余默认折叠

这样做的目的：

* 折叠状态交给 Blender 自动管理，减少 `show_*` 属性数量与重复 UI 代码

* 用户通过面板标题快速定位：不需要先展开/收起一堆 Box 才知道每段内容是什么

### 建议分组（以用户任务路径为主线）

建议把功能按“用户在做什么”组织成 6\~8 个块（顺序即默认视觉顺序）：

* <br />

  1. 状态与引导

  * 就绪/处理中/缺工具提示（保留现有优点）

  * 显示“上次图片/上次批次”摘要（可一眼确认是否在处理正确的素材）

* <br />

  1. 开始制作（核心入口）

  * 主要按钮：选择图片开始制作（强调主按钮视觉权重）

  * 可选：批量模式提示（你已经支持多选文件，UI 可以明确这一点）

* <br />

  1. 快捷调整（低成本、可逆操作）

  * 锁定误选、使用 3D 游标、同步导入图像、原点模式（保留现有“快速模型调整/原点位置”理念）

  * 原点模式可以附带“推荐/风险提示”的文案（避免用户误选导致的未知 bug）

* <br />

  1. 参数（从“最常用”到“需要理解”的层级）

  * 图像预处理：扩展/平滑/阈值

  * 建模：缩放/厚度/挤出模式/倒角

  * 底板与插脚：开关 → 尺寸 → 材质（保持层级嵌套，但尽量减少嵌套层数）

* <br />

  1. 材质（与结果外观相关，通常在生成后会调）

  * 立牌材质：指定材质 + 一键创建默认

  * 彩窗：材质选择 + 多彩模式 + 一键生成（基于选中物体）

* <br />

  1. 管理（不会影响参数，但影响场景与文件）

  * 再次生成、选择/定位本批次集合、删除选中、删除所有（危险操作集中放）

  * “恢复默认数值”建议拆成：恢复本区默认 / 全部恢复（降低误操作代价）

* <br />

  1. 高级 / 诊断（给高级用户、排错用）

  * 外部工具检查详情与“如何安装/配置”链接或提示（现在只有缺失列表，缺少下一步指引）

  * 临时目录/素材目录快捷打开（你已有 assets/temp 的概念，UI 可提供入口）

## 交互与外观优化点（你可能没显式考虑到的）

- 破坏性操作的防呆：将“删除所有”等重要操作改为需要二次确认（Operator `invoke` 弹确认对话框），并在 UI 上用 `alert=True` 或红色语义提示强化风险。
- 二次确认的偏好设置开关（你补充的关键点）：
  - 在插件偏好设置中增加“安全确认”分组（见 [preferences.py](file:///e:/b-2_code/2026_02_23_digital_merch_factory/preferences.py) 的既有分组风格）。
  - 提供一个总开关：`启用重要操作二次确认`（默认开启）。
  - 提供每个重要按钮的独立开关（默认开启），例如：
    - 删除所有脚本模型：二次确认
    - 删除选中立牌（按集合删除）：二次确认
    - 恢复默认数值：二次确认
  - UI/Operator 侧的行为规则：当总开关关闭时，无视单项开关；当总开关开启时，按单项开关决定是否弹确认框。

* 上下文禁用：当缺外部工具 / 正在处理中 / 没有有效选中对象时，对应按钮灰显，而不是允许点击后再报错（减少挫败感）。

* 状态反馈的颗粒度：批处理时，除了当前文件名，可显示“成功/失败计数”和“是否将结果放入同一批次集合”的信息。


* 文案一致性与可扫描性：统一用动词开头（生成/删除/创建/重置），避免同一层级混用中英文（现在顶部标题是英文）。

* 主题与字体兼容：避免使用 emoji 作为关键 UI 信息（主题/字体不一致时容易错位），尽量使用 Blender 内置 icon 表达风险/状态。

## 落地实施路径（分步迭代，确保“能跑”）

### 第 1 阶段：信息架构落地（不改功能逻辑，只重排 UI）

* 将现有单一面板拆分为“主面板 + 子面板”，并用 `bl_parent_id`、`bl_order` 固定顺序。

* 保留现有属性与 Operator，不改业务行为；仅调整 UI 入口与分组。

* 目标：用户在 10 秒内能看懂“从哪开始、现在是什么状态、结果在哪管理”。

### 第 2 阶段：减少重复 UI 代码（DRY、可维护）

* 选择两条路线其一（执行阶段再定）：

  * 路线 A（推荐）：完全切换到 Sub-panel 管理折叠，逐步移除 `show_*` 折叠属性

  * 路线 B（折中）：保留当前折叠，但把“折叠头绘制 + 返回 box/body 容器”的逻辑封装为通用函数，减少重复

* 目标：UI 文件可读性提升，新增一段设置不需要复制粘贴 10 行布局代码。

### 第 3 阶段：人类操作习惯增强（防呆、引导、快捷入口）

* 为危险操作加确认与更明确的风险提示。

* 为“依赖上下文”的按钮加 `enabled/active` 控制。

* 增加“上次处理摘要”“一键定位批次”“打开素材/临时目录”等高频小工具。

### 第 4 阶段：外观与一致性收尾（更像原生）

* 统一标题语言与术语；统一各区 `use_property_split` 的使用策略（避免 checkbox/enum 被 split 后可读性下降）。

* 统一 icon 风格：状态用 `INFO/ERROR/CHECKMARK/SORTTIME`，操作用 `FILE_NEW/FILE_REFRESH/TRASH` 等动词 icon。

* 对“高级/诊断”面板设置默认折叠，避免吓到新手。

## 交付物（执行阶段会产生的改动范围）

## 验证标准（执行阶段验收用）

* 新用户路径：打开面板后能立即看到“开始制作”入口与当前状态。

* 旧功能回归：选择图片生成、再次生成、删除选中/删除所有、材质创建、彩窗生成均能在新布局中找到并可用。

* 防呆：缺工具/处理中时，用户不会误触关键按钮；危险操作有明确确认步骤。
